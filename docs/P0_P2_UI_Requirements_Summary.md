# LLA P0–P2 与 UI 需求汇总

> 本文件只汇总已存在的开发规格与验收约束，不修改任何原始验收标准。P1 的独立验收文本来自项目提供的 `LLA P1 Acceptance Test V1.0`；P0、P2 和 Homepage UI 的原始文件仍是最终依据。

## 1. 版本边界与共同原则

- P0 是训练核心的权威层：状态、评分、完成条件和有效学习时长必须由可恢复的本地数据记录决定，不能依赖聊天上下文或 LLM 自由判断。
- P1 在不改变 P0 训练核心的前提下，增加候选素材获取、质量筛选、用户确认准备和正式难度升级。
- P2 是长期观察、解释、记忆深化和难度历史层，只能增加派生视图、配置、审计和历史事件，不能静默改写 P0/P1 源事实。
- 所有阶段都要求失败可解释、操作可重试、关键写入幂等、源数据可追溯；自动测试通过不能替代运行态和持久化证据。

## 2. P0：可恢复的高强度训练闭环

### 核心流程

1. 使用预置素材，校验音频与完整 Transcript，按自然句/意群拆成三个语义完整 Part。
2. 第一次完整盲听；在此之前不得暴露字幕、原文或关键词。
3. 首次理解检查：四档自评（`<30%`、`30–50%`、`50–70%`、`>70%`）和简短概述。
4. Dictation Part 1/2/3：逐句训练，记录每次播放、尝试、Hint、Reveal 和错误类型；通过标准为逐字正确，允许约定的等价书写。
5. 三个听写 Part 完成后，第二次完整听全文，并进行第二次理解复测。
6. Reading Part 1/2/3：原音、连续跟读、段尾反馈；语速、停顿、重音三维独立判定，不做平均抵消。
7. 三个 Reading Part 达标后，进行全文连续朗读验收；失败时定位主要问题 Part 并回练。
8. 完成状态区分 `LISTENING_COMPLETED` 与 `FULLY_COMPLETED`；允许跨天、跳过朗读和断点恢复。

### 周测、强化与统计

- 没有朗读训练时只做听写周测；有朗读训练时增加朗读周测。
- 听写周测低于 80%，或朗读任一关键维度未达标，进入 `REINFORCEMENT_REQUIRED`。
- 强化包只覆盖失败能力，规模约为原周测的 30%–50%；强化完成后只做针对性复测。
- 有效学习时间仅统计闭合的训练活动：盲听、听写、复听、朗读、全文验收、周测、强化与复测；保存 session、weekly、total 原始时长。
- 朗读/ASR/分析失败不得错误写入 PASS；录音应保留并允许重新分析。

## 3. P1：候选素材与正式难度升级

### 候选素材管线

- Stage 1 默认使用 VOA Slow English；候选必须具备 Provider ID、标题、音频、Transcript 和时长等关键字段。
- 默认目标时长为 15–20 分钟，边界值可接受，超出范围不得进入默认候选。
- 音频质量分为 `Clear`、`Acceptable`、`Poor`：优先展示 Clear，不足三条时用 Acceptable 补位，Poor 永远不可见、不可选、不可 prepare。
- Transcript 缺失、不完整、错配或下载失败必须淘汰并保留原因；质量检测器、配置版本、指标/失败原因、时间和音频指纹应可审计。
- 每批最多展示三条；少于三条返回实际数量；同一 Provider 指纹不得在同批次重复。
- 候选先处于 `CANDIDATE`，只有用户选择且 prepare 成功后才能创建带 `source_candidate_id` 的 READY Material；失败不得产生 READY 假记录。
- 搜索、质量分析、prepare 支持有界重试、错误恢复、并发安全和幂等；P1 候选不得污染 P0 正式素材列表或训练状态。

### 难度升级

- Stage 1 → Stage 2 → Stage 3，只允许逐级升级，Stage 3 封顶。
- 连续 8 个稳定训练周满足 Weekly Gate、听写 ≥80%、朗读（如有）通过且无强化后，只生成资格/提示，不能自动升级。
- 必须经用户 `UPGRADE_CONFIRMED` 才升级；每次最多改变一个变量，即 `speed_stage`，时长目标保持不变。
- `KEEP_CURRENT` 或 `DECIDE_LATER` 后至少冷却 4 周；冷却期间不重复提示、不延长冷却、不重复计数。
- 周缺失、Gate 失败、朗读失败、强化状态或阶段切换必须正确重置/隔离连续计数；P0 训练、评分和历史字段语义保持不变。

## 4. P2：长期观察、记忆深化与难度历史

### P2-1 长期仪表盘

- 支持完整历史、近期范围和任意日期范围；响应必须显式返回起止日期、粒度、时区/时间解释、来源规则和空周期行为。
- 展示有效总学习小时、选定范围小时、正式 Stage、Weekly Gate 状态和复习建议状态。
- 首次理解曲线固定映射：`<30% → 15`、`30–50% → 40`、`50–70% → 60`、`>70% → 85`；保留 raw band、mapping version 和样本数；不得用 SECOND 替代缺失 FIRST。
- Weekly Test 保留原始听写分数、题目数、Gate、强化和复测状态，不以 Gate 结果覆盖原分数。
- 朗读趋势分开呈现 speed、pause、stress；不合成为单一平均分，不从状态字段伪造数值 stress。
- 空数据、缺失数据和分析失败必须区分显示，不能把缺失当 0 或 FAIL。

### P2-2 Listening Memory

- 以 Target、Occurrence、Recognition Episode、Aggregate 四层组织普通训练听辨证据；重试不应被误计为多个独立 Episode。
- `first_correct_listen_count` 使用第一次无 Hint、无 Reveal 的 exact 结果中的 `listen_count`；不能用 `attempt_number` 替代。
- Hint 后正确、Reveal 后正确不计入首次正确听辨均值；Reveal 仍可作为困难证据。
- `SPELLING` 单独错误不得进入听力困难统计；普通训练和 Weekly Test Memory 必须隔离。
- 用户可配置短期/长期窗口、最少 Episode 数、最少日期数；配置必须版本化，非法窗口显式报错，未配置返回 `UNCONFIGURED`，禁止隐藏默认值。
- 历史回填必须保留原始记录并写入来源、字段、时间、版本和可靠性；复习建议默认开启，支持频率限制、暂停、恢复、按目标禁用和历史删除而不删除原始训练。

### P2-3 难度历史

- 使用 P1 `weekly_gate_records` 等正式事实，不使用 legacy recommender 推断正式 streak。
- 以 append-only 事件记录 Gate、Eligibility、Prompt、Decision、Cooldown、Stage Change、降级建议和确认降级，事件包含时间、前后 Stage、来源记录、actor、原因和策略版本。
- 升级、拒绝、延迟、4 周冷却、Stage 变更和降级都必须可解释、可查询、可幂等。
- 连续两周未通过只产生降级建议；必须用户确认，且一次最多降一级并重置相关计数。
- P2 读取不应创建重复源记录或历史记录；所有派生结果可由持久化源事实重新计算。

## 5. UI V1 需求

### 信息架构

- 首页只突出三件事：当前训练、当前素材/新素材、训练方式；顺序固定，当前训练视觉优先级最高。
- 使用窄侧栏：桌面宽度约 208px，短标签、低饱和 active 填充；标题弱化为 20–24px 常规/中等字重。
- 当前训练使用唯一主 Hero 卡片和一个主要动作；素材卡片承担当前/新素材入口；训练方式使用轻量操作卡，不做营销卡、课程卡或游戏化。
- 明确提供 Loading、Empty、Error、Disabled、Focus 等状态；错误不能只靠颜色表达，必须有文字和恢复动作。

### 视觉与响应式

- 画布冷灰 `#F4F6F8`，表面白色，边框 `#E0E6EA`，主文字 `#26313A`，次文字 `#64727C`，弱文字 `#8B979F`。
- 当前训练使用蓝灰 `#7F98AA`，素材使用青灰 `#7FA9A7`，训练方式使用紫灰 `#928EAA`；完成、警告、错误、信息状态分别使用低饱和状态色。
- 使用 4px 间距基线；Hero 内边距约 32–48px，普通卡片约 16–24px；避免默认全胶囊按钮，按钮/标签/输入框圆角约 10–12px。
- 桌面、768–1199px 中等宽度和小于 768px 窄屏均不得横向溢出；窄屏卡片堆叠，触控目标至少 44px，关键状态不得通过隐藏或过度截断来适配。
- UI 只负责呈现与交互，不改变 P0/P1/P2 业务规则、API 数据契约或权威状态机。

## 6. 固定版本的验收门槛

1. `pytest -q` 全部通过，包含 P0 acceptance、P1 关键规则和 P2 测试。
2. 前端生产构建通过，且无工作区格式错误。
3. P0/P1/P2 运行态关键入口、API/持久化事实和错误恢复有证据；不能只凭页面能打开、单元测试或截图判定。
4. UI 在 1440×900、1024×768、390×844 下无横向溢出，首页层级、颜色、焦点环、触控尺寸和入口行为通过检查。
5. 变更仅限已授权范围；完成提交后推送当前 Git 远端，并记录提交号与推送结果。

## 7. 不在本次自行扩大的事项

- P0 具体首批素材清单、Hint 文案、周测题量/组合与精确计分口径、朗读阈值和模型参数继续以现有配置/验收样本为准。
- 不新增多用户、云同步、社交、游戏化、课程管理或移动原生 App。
- 不用累计学习小时自动触发 P1 升级/降级，不引入新的 WPM 升级算法，不把 LLM 输出当作权威证据。
