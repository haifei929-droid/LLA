## 1. 问题与目标

用户目前停留在素材页面：不能选择本地音频上传，看不到联网获取结果，也不能将待审核素材推进到训练。核心目标是让用户在浏览器内完成：

**选择本地音频或获取官方音频 → 准备文字稿 → 对齐与试听校对 → 明确审核 → 合格素材入池 → 开始既有训练。**

下载成功、文件存在、隔离入库、审核通过、进入当前档位可选池必须分别展示，不能统一称为“可训练”。网络仅自动获取既有策略允许的 50languages 官方音频包；不承诺自动取得官方文字稿。

## 3. Scope

### IN SCOPE

1. 素材页本地文件上传、文字稿输入和受控持久化。
2. 既有单一主源采集能力的页面入口、已有暂存文件展示及失败重试。
3. 待处理素材列表、文字稿校对、已有对齐能力接入、审核与明确失败提示。
4. 审核通过后通过既有素材池和训练入口开始学习。
5. 上述调用链必要的 API、服务校验、针对性测试及浏览器验收。

### OUT OF SCOPE

- 新增素材平台、任意 URL 抓取、全站爬取、绕过限制、自动取得受限文字稿。
- 后台定时采集、复杂任务队列、新数据库、新管理系统、新大型框架。
- 自动认定英音、自动批准 ASR 草稿、降低许可或稿音一致性要求。
- 难度阈值重新标定、训练状态机重写、历史数据清理、无关重构。
- 重开已关闭缺陷；发现新回归时单独记录实际复现证据。

## 4. 用户操作与行为要求

### 4.1 本地导入

- 将手填服务器路径的主入口替换为浏览器文件选择；支持现有 `AUDIO_SUFFIXES`（MP3/WAV/M4A/FLAC），文字稿可上传 UTF-8 TXT 或直接粘贴。
- 标题可从文件名生成并允许修改；内部 ID 由后端稳定生成，不要求用户理解数据库标识。保留实际来源平台、课程、原始条目/顺序等可填写信息，不默认将本地上传声明为 50languages。
- 只有音频也允许暂存，清楚标为“待补文字稿”；文字稿缺失时不能导入为可训练素材。
- 文件放到由配置确定的受控目录，后端生成文件名，不接受客户端绝对路径、目录穿越、任意覆盖或任意文件读取。按实际字节实施上传大小限制并在页面提示；检查可解码性，失败不留下正式素材。
- 浏览器重复提交、重试不制造重复条目；复用既有来源身份去重，本地上传补足稳定文件身份。若有重复，返回已有条目及清楚提示，不生成随机 ID 绕过去重。

### 4.2 官方音频获取

- 展示当前 Active Source；没有主源时，提供用户明确确认启用的操作，复用既有主源治理规则。不得因点击下载而静默激活或切换来源。
- 已存在主源时保持锁定；来源不匹配返回已有错误，不抓取其他网站。平台切换仍需满足既有完成条件与用户确认。
- “获取官方音频”调用既有 `fetch_official_pack`，优先复用有效缓存；状态至少涵盖执行中、完成、失败和可重试。无需为本轮增加后台调度服务；请求执行中禁用重复按钮，后端也防止并发写同一缓存。
- 首次打开页面应能看到既有暂存批次，不能只展示本次页面上传产生的文件，也不能靠重新下载来刷新列表。
- 音频数、已有文字稿数、待审核数、正式入库数分别统计。默认按课程原始顺序展示，不随机混合来源。
- BC/BNE 不发探测或抓取请求；50languages 文字页不抓取。页面明确说明“自动获取音频；文字稿需准备和校对”。

### 4.3 文字稿、对齐与审核

- 待处理条目提供原音频试听、文字稿查看/修改、对齐操作与句子片段试听；复用已有转写和对齐函数。ASR 可作为显式可选的草稿操作，不是审核替代品。
- 对齐依赖缺失、模型不可用、对齐失败或存在未匹配句子时，保留工作内容并提示原因；不得改用固定 8 秒或按字数估算后声称已验证。不得静默下载大型模型。
- 修改文字稿使旧对齐和审核证据失效；后端验证对齐属于当前音频及当前稿件，防止陈旧结果复用。已有训练中的正式素材不在本轮直接原地改稿。
- 审核展示来源、英音依据、许可依据、音质和稿音/边界检查结果，用户明确确认后才提交。音频许可不能自动覆盖文字稿许可；来源标识不能证明口音。
- API 必须独立校验准入条件，不能仅靠前端勾选。禁止信任客户端直接传入 `INGESTED`；未知口音、en-US、许可未确认、文字稿未确认、音质不合格、缺少难度分数或对齐不完整均不得提升为正式素材。
- 复用 `LocalImportService` 和既有审核规则，但先检查其前置条件是否足够。现有 `approve` 主要检查难度分数并更新字段，不可直接原样暴露为无条件批准接口；在本调用链补齐必要后端校验。
- 只有音频的暂存文件无需伪造文字稿或空素材行。状态以已有数据库字段和批次文件证据推导；不要额外建立平行状态机或重复素材数据库。

### 4.4 入池与开始训练

- 状态展示至少区分：仅音频/待补文字稿、待校对或对齐、待审核、审核未通过、正式入库、当前档位可选。
- 复用 `MaterialPoolService`，保持按 scope 取档、来源与课程连续性；审核通过不等于在所有档位可选。
- 对符合当前档位及来源规则的条目提供“开始训练”，进入现有训练流程；不合条件时解释原因，不绕过选材规则。
- 网络不可用时仍可查看、播放和使用本地合格素材。刷新页面后暂存文件、校对内容与审核状态仍在。
- 取消页面中“MaterialProvider 接入后开放”等过时技术占位文案；反馈以用户可理解的操作、状态和原因描述。

## 6. 生产数据与执行边界

- 禁止用生产 `data/language_training.sqlite3` 运行测试、迁移、自动审批或清理；禁止删除生产缓存制造故障。
- 所有验证使用仓库外临时根目录、生产库副本或独立夹具。设置 `LTA_PROJECT_ROOT`，同时显式设置 `LTA_DATABASE_PATH`、`LTA_MATERIALS_DIR`、`LTA_RECORDINGS_DIR`、`LTA_PROCESSED_DIR`。暂存、缓存、上传及对齐结果也必须落在该临时根目录。
- 测试前后记录生产库与缓存指纹、HEAD 和 status；不得绕过 `conftest.py` 数据安全护栏。复制数据库须在一致性条件下执行，有活跃写入时使用 SQLite 安全备份，不只复制主文件忽略 WAL。
- 列表、状态查询不得触发下载、转写、审批或迁移；下载只在明确操作时执行。应用现有启动行为如有初始化，浏览器验证也必须指向隔离配置。
- 保持 Backend Transition Authority、operation_id 幂等、Part 完成、盲听、三段听写、逐字判断、朗读、周测、跨天恢复、累计时间和 8 周用户确认升级机制。
- 保留原始完整短课，不新增整篇 15–20 分钟门槛，不强制切成独立 2 分钟文件，不使用 TTS 代替原音频。

## 7. 验收矩阵

| 编号 | 场景 | 必须看到的结果 |
|---|---|---|
| A1 | 浏览器选择音频和稿件 | 无需输入服务器路径或运行命令；受控目录保存，初始不能训练 |
| A2 | 音频无稿、损坏音频、超限文件、恶意文件名 | 无稿可暂存；其他输入明确拒绝；不越界写入、不污染正式库 |
| A3 | 同文件重复上传、双击、请求失败后重试 | 无重复正式素材、无相互覆盖，能返回已有项 |
| A4 | 页面打开已有隔离批次 | 音频与文字稿状态正确显示，不自动下载或认定已校对 |
| B1 | 无主源 / 主源不匹配 | 按既有治理规则拒绝；无未授权网络请求、无隐式切换 |
| B2 | 页面获取官方音频 | 真实许可范围内网络获取成功、文件可解码播放、结果在页面可见；只访问允许的官方资源 |
| B3 | 缓存命中、网络失败、并发点击 | 缓存可复用，失败可重试，无坏正式文件；禁止平台零请求 |
| C1 | 校对、执行对齐、试听句子 | 边界来自当前音频/稿件，试听与内容对应，无固定 8 秒伪造 |
| C2 | 改稿、未匹配句子、缺模型、ASR 未校对 | 明确阻断审核，工作内容保存，旧证据失效 |
| C3 | 直接调用审批 API 提交未知口音、美音、缺许可或不完整证据 | 后端拒绝，不因绕过 UI 而正式入库 |
| C4 | 完整证据并由用户确认 | 幂等入库、来源与审核依据可追溯；符合档位的素材进入可选池 |
| D1 | 从素材页开始训练 | 经既有规则选中已审核素材，实际音频播放，进入既有训练状态机 |
| D2 | 刷新、重启、次日继续及断网 | 数据与进度保持，本地训练可用；断网只影响需要网络的操作 |
| D3 | 全量回归及数据边界 | 原训练测试通过，生产指纹不变，未引入无关改动 |

至少提供两条浏览器实际操作证据：①本地文件导入至训练；②官方音频获取、准备文字稿、审核至训练。真实稿音匹配需试听与人工确认，Mock 或自动对齐分数不能替代。允许只选同课程 1–3 课完成真实审核；官方整包是既有唯一下载单元，不扩展到批量全库审核。

真实网络不可用标 BLOCKED，不用 Mock 宣称联网 PASS；缓存命中仅证明缓存复用，不能替代首次网络下载证据。没有合规且已校对稿件时，真实审批/训练闭环仍为 BLOCKED，但隔离夹具可验证接口行为。不得为了 Close 自动把现有 5 个 TXT 标为已校对。
